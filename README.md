# 💗 산업공학과 최적화 소개팅

기존 시제품의 분홍색 카드·버튼 디자인을 유지한 공용 기기용 웹 프로그램입니다.
운영진 기본 비밀번호는 **1010**입니다. HTML에서 화면만 가리는 방식이 아니라 서버가 비밀번호와 세션을 확인합니다.

## 노트북 한 대로 실행

Python 3.10 이상을 설치하고, 압축 파일을 푼 폴더에서 실행합니다. 추가 라이브러리는 필요 없습니다.

```sh
python server.py
```

macOS에서는 `python3 server.py`를 사용하세요. Windows에서는 `실행-Windows.bat`를 더블클릭해도 됩니다.
실행 후 **노트북 브라우저 주소창**에 `http://127.0.0.1:8000`을 입력하세요.
`index.html`만 더블클릭하면 서버 저장과 운영진 인증은 동작하지 않습니다.

이 프로젝트는 파일과 실행 가능한 서버를 제공하며, 외부 클라우드에 배포된 상태는 아닙니다.
기본 실행은 노트북 내부에서만 접속할 수 있습니다. 서버를 종료해도 이미 저장된 데이터는 유지됩니다.

## 이전 버전에서 업데이트

이미 참가자 데이터가 있다면 먼저 운영진 화면에서 백업을 다운로드하세요.

1. VS Code에서 실행 중인 서버 터미널을 클릭하고 **Ctrl+C**를 눌러 서버를 종료합니다.
2. 새 ZIP을 **다른 폴더에 압축 해제**합니다. 기존 폴더와 `data` 폴더는 삭제하지 마세요.
3. 새 폴더의 **`server.py`, `index.html`, `실행-Windows.bat`**만 기존 프로그램 폴더에 복사해 덮어씁니다.
4. 기존 `data` 폴더는 그대로 두고 서버를 다시 실행한 뒤 크롬에서 **Ctrl+Shift+R**을 누릅니다.

VS Code에서 실행하려면 `server.py` 탭 → **Ctrl+Shift+P** → **Python: Run Python File in Terminal**을 선택하세요.
`py` 명령이 없는 Windows에서도 VS Code에 선택된 Python으로 실행할 수 있습니다.

## 운영 순서

1. 결제는 현장에서 운영진이 별도로 확인합니다. 앱에서는 결제 확인·사전 번호 발급·입력 화면 열기를 요구하지 않습니다.
2. 참가자는 첫 화면에서 바로 남성/여성을 선택하고 6개 성향·선호·중요도·인스타 아이디를 작성합니다.
3. 제출 전 인스타 아이디를 재확인합니다. 서버에 응답이 저장되면 참가번호가 **1번, 2번, 3번…** 순서로 자동 발급됩니다. 두 기기를 함께 쓰면 같은 서버에서 저장 완료 순서대로 번호를 부여합니다.
4. **접수 완료 화면**까지 확인합니다. 저장 미확인 안내가 나오면 입력을 유지하고 연결을 복구하세요.
5. **입력 종료 · 다음 참가자**를 누르면 새 입력 화면이 바로 열립니다. 완료 화면은 20초 뒤에도 자동 초기화됩니다.
6. 마감 후 운영진 관리 → 비밀번호 `1010` → 명단·참석·결제 명단 대조 → 필요 시 접수 취소.
7. 전체 백업을 내려받고 매칭 결과를 생성합니다. 결과의 DM 문구를 복사해 **인스타에서 직접 발송**하고 발송 상태를 기록합니다. 자동 DM 발송 기능은 없습니다.
8. 발송이 끝나면 백업을 다시 내려받습니다. 발송을 시작한 뒤에는 재매칭하거나 참가자를 추가하지 마세요.

관리 화면에서 **운영진 화면 잠금** 또는 **참가 신청**을 누르면 명단을 지우고 바로 입력 화면으로 돌아갑니다.
다음 회차는 별도의 데이터 폴더로 서버를 다시 시작하세요.

운영진 화면은 3분 동안 조작하지 않으면 잠깁니다. 서버 측 운영진 세션은 로그인 후 30분 유효합니다.
공용 기기 브라우저의 자동완성·비밀번호 저장을 끄고, 참가자가 입력 후 반드시 화면을 종료하도록 운영하세요.
앱이 운영진 화면을 잠글 때 명단과 결과를 화면에서 제거하지만, 기기의 OS 잠금과 브라우저 관리는 별도로 필요합니다.

## 테스트 후 전체 초기화

운영진 화면에서 **전체 데이터 초기화** → 비밀번호 **1010** 다시 입력 → **백업 후 전체 초기화**를 누릅니다.
참가자·참가번호·매칭 결과·DM 발송 기록을 모두 비워 새로 테스트할 수 있습니다. 서버를 끄거나 data 폴더를 직접 옮길 필요가 없습니다. **초기화 후 참가번호는 다시 1번부터 시작합니다.**

- 초기화 전 원본 전체를 `data/reset-backups/`에 자동 백업합니다. 백업 생성 또는 무결성 확인에 실패하면 초기화하지 않습니다.
- 초기화 전 백업은 일반 자동 백업 100개 정리 대상에 포함하지 않습니다. 기존 다운로드·자동 백업도 유지됩니다.
- 응답이 끊겨 같은 초기화를 재시도해도 이미 완료된 작업을 다시 실행하지 않습니다.
- 입력 중인 다른 기기가 있으면 접수를 중단하고, 초기화 후 모든 기기의 화면을 새로고침하세요. 초기화 전 입력의 재전송은 차단되며, 새로고침 시 이전 임시 응답을 비웁니다.
- 초기화는 현재 운영 명단을 비우는 기능입니다. 개인정보 보관 기한이 끝나면 `reset-backups` 등 모든 백업 복사본도 별도로 삭제해야 합니다.

## 태블릿 또는 두 기기를 함께 사용

태블릿만으로 HTML을 여는 대신 **노트북 또는 별도 서버에서 Python 서버를 실행**해야 합니다.
모든 기기는 **같은 서버**에 접속해야 명단이 합쳐집니다. 각 기기에서 별도로 서버를 실행하면 데이터가 나뉩니다.

신뢰할 수 있는 사설 네트워크에서 서버를 연결할 때는 다음과 같이 수신 주소를 지정할 수 있습니다.

```sh
python server.py --host 0.0.0.0 --port 8000
```

태블릿에서 노트북의 사설 IP와 포트로 접속합니다. 방화벽과 네트워크의 기기 간 통신 허용 여부도 확인하세요.
이 프로그램의 기본 HTTP 서버는 로컬 사용을 위한 구성입니다. **공개 인터넷이나 공용 Wi-Fi를 통해 운영하려면 HTTPS 역방향 프록시와 영구 저장 공간을 갖춘 서버 배포가 필요합니다.**
HTTPS로 배포할 때 `COOKIE_SECURE=1`을 설정하세요. 운영진 PIN은 서버 환경변수 `ADMIN_PIN`으로 변경할 수 있습니다.
서버 데이터 폴더를 정적 웹 공개 폴더로 노출하지 마세요. 서버를 재시작하면 로그인은 다시 해야 합니다.

## 데이터 저장과 백업

- 기존 참가자는 업데이트 후 기존 접수 순서대로 짧은 번호가 부여됩니다. 취소한 번호는 재사용하지 않고, 새로고침·재전송·서버 재시작으로 번호가 바뀌지 않습니다. 내부의 긴 식별자는 중복 제출 방지에 계속 사용하며, 완료 화면·명단·DM 문구에는 짧은 번호를 표시합니다.
- `data/festival.sqlite3`: 서버 원본. SQLite 트랜잭션과 WAL, FULL 동기화를 사용합니다.
- `data/backups/`: 참가자 접수 후 자동 생성되는 일관된 SQLite 백업, 최신 100개 유지.
- 운영진 **전체 백업 다운로드**: 참가자·자동 발급 참가번호·매칭 결과·DM 발송 상태를 담은 백업.
- 입력 중 응답은 해당 탭의 `sessionStorage`에 임시 보관합니다. 최종 저장 성공 시 제거합니다. 저장 확인 전에 새로고침해도 같은 접수 식별자로 복구·재전송합니다.
- 네트워크 오류 시 입력을 유지하고 재전송합니다. 같은 접수번호는 한 번만 저장되므로 응답 유실 후 재시도해도 중복되지 않습니다. 입력 오류·중복 계정 오류는 자동 반복하지 않고 수정을 안내합니다.
- 자동 백업 실패 시에도 원본 커밋이 완료됐으면 저장 성공과 백업 경고를 함께 표시합니다.

**서버에 저장된다는 것이 외부 클라우드에 복제된다는 뜻은 아닙니다.** 서버 내부 백업도 같은 디스크이므로 노트북 분실·고장까지 막지는 못합니다. 회차별로 백업 파일을 다른 기기나 접근 제한된 저장소에도 보관하세요.
기기 임시 보관은 접수 완료가 아니며, 탭을 닫거나 기기를 잃으면 미전송 응답을 잃을 수 있습니다.

앱의 동의문에는 행사 종료 후 **7일 이내 삭제**를 기본 정책으로 명시했습니다. 행사 공지와 맞는지 운영 전에 확인하고, 그 기한에 원본 폴더·자동 백업·다운로드·외부 복사본을 모두 삭제해야 합니다. 자동 기한 삭제 기능은 없습니다.
환불 여부는 운영진이 실제 결제 수단에서 별도로 처리해야 합니다. 앱의 취소 처리는 매칭 대상 제외 기록입니다.

### 복구

서버를 종료하고 기존 `data` 폴더를 별도로 보존한 후, 비어 있는 데이터 폴더로 복구합니다.

```sh
python server.py --restore festival-backup.sqlite3
```

기존 원본이 존재하면 덮어쓰지 않고 중단합니다. 복구 시 백업 무결성을 검사합니다.
복구 후 운영진 화면에서 접수 인원·접수번호·매칭 결과·발송 상태를 결제 명단과 대조하세요.

서버 데이터 위치는 `MATCH_DATA_DIR` 환경변수로 지정할 수 있습니다. 새 회차를 시작할 때 별도 폴더를 지정하면 앞 회차를 보존할 수 있습니다.
단일 회차 최대 400명을 지원하며, 회차 마감 시 별도의 결제 명단과 저장된 참가자 목록을 대조하세요.

## 문항과 점수

- 외적 이미지: 강아지상 / 고양이상 / 곰상 / 여우상
- 사교 성향: 조용한 편 / 중간 / 활발한 편
- 데이트 취향: 실내 / 야외 / 둘 다
- 계획 성향: 즉흥적 / 중간 / 계획적
- 테토·에겐 스타일: 테토형 / 에겐형 / 반반 (본인이 생각하는 분위기를 묻는 재미 문항)
- 애정 표현 방식: 말로 표현 / 행동으로 챙김 / 둘 다

각 항목에서 본인의 성향 하나와 원하는 상대 성향을 선택합니다. 상대 성향은 복수 선택 또는 상관없음입니다.
서로 다른 중요도 1순위·2순위를 선택하며 가중치는 3·2·1·1·1·1입니다.

개인 선호 점수 = 100 × Σ(가중치 × 일치도) / 9.
정확한 선호 일치와 상관없음은 1, 사교·계획 성향에서 한 단계 차이는 0.5, 나머지 불일치는 0입니다.
데이트 취향과 애정 표현 방식의 '둘 다'는 두 가지 모두 허용하므로 충족으로 취급합니다. 테토·에겐의 '반반'은 독립된 선택지이며 자동으로 다른 선택지와 일치시키지 않습니다.
상호 점수 = √(A가 B를 선호하는 점수 × B가 A를 선호하는 점수).

배정은 남녀 간 일대일이며 **매칭 수 최대 → 가장 낮은 개인 선호 점수 최대 → 상호 점수 합 최대**의 순서를 지킵니다.
선호 불일치를 금지 조건으로 사용하지 않아 매칭 수는 두 그룹 중 적은 인원수입니다.
최저 개인 선호점수 기준을 이분 탐색하고, 그 기준 안에서 헝가리안 알고리즘으로 합계를 최대화합니다.
동점은 고정된 참가번호 순서로 결정합니다. 이 점수는 취향 충족도이며 실제 호감이나 연애 성공 확률이 아닙니다.
참가자 명단이나 배점 버전이 바뀌면 기존 결과가 만료되고 이전 결과는 데이터베이스에 남습니다.

기존 4문항 응답과 백업은 수정·삭제하지 않습니다. 추가 두 항목에 응답이 없는 참가자는 없는 답을 추정하지 않고, 각 방향에서 확인 가능한 항목의 가중치 합으로 점수를 환산합니다. 이전 버전에서 발급만 하고 제출하지 않은 번호는 새 매칭을 막지 않습니다.

## 검증

```sh
python -m unittest discover -s tests -v
```

로그인 없는 접수·6문항 검증·중복 재전송·운영진 권한·백업 무결성과 복구·이전 데이터 호환·결과 만료·초기화 권한·복구용 백업·실패 시 데이터 보존·중복 초기화 방지·초기화 전 입력 차단·연속 참가번호·재시도·동시 접수·기존 번호 호환을 검증합니다.
소규모 전체 배정 경우의 수와 비교해 최저점 및 총점의 최적성도 검증합니다.
실제 Chromium에서 두 참가자 접수, PIN 검증, 매칭, DM 상태 변경, 백업 다운로드, 화면 잠금과 모바일 너비도 확인했습니다. 접수 중 연결을 끊고 복구했을 때 접수 완료를 잘못 표시하지 않고 응답을 보존해 재전송하는 과정도 확인했습니다.
